## 1. 产品定位与差异化（8.5 → 目标稳住并说清）

**现状：**「馆藏取证 + 关系编织 + 可带走的书」差异清楚。  
**风险：**用户仍可能把它理解成「又一个 AI 路线生成器」。

**建议：**

1. **【可施工】** 首屏只钉一句话差异：继续强化「目录给条目，我们给关系」；Brief 区避免出现模型/API/技术词。
2. **【可施工】** 把「不做」写进产品边界：不做实时导航、不做景点点评聚合、不编造无出处史实。
3. **【可施工】** 差异验证场景固定 2 个演示 CTA 文案；**【可持续优化】** 对外材料一律不扩到未就绪城。

**可验收：**任意新用户 10 秒内能复述「和普通路线 App 的一点不同」。

## 2. 品牌与视觉气质（8.0 → 克制加强）

**现状：**纸书 + 红鸢气质统一，优于通用 AI 壳。  
**风险：**局部仍出现工程 jargon（曾用 BYOK）、失败页偏运维口吻、favicon/品牌资产易缓存漂移。

**建议：**

1. **【可施工 · 大半已做】** 用户可见文案零 jargon；代码注释里的 BYOK 可留。
2. **【可施工】** 失败页改读者口吻：`App.tsx` degraded 卡去掉「演示降级/运维」腔，改「未编造故不展示」+ 可展开技术说明。
3. **【可施工 · 已做】** favicon 多格式 + `?v=`；发版时记得同步 hub `/favicon.ico`。
4. **【可持续优化】** 红鸢形象保持轻量，勿做成独立 IP。

**可验收：**截图抹掉导航后，仍能一眼认出是红鸢而不是别的产品。

---

## 3. 主流程完整度（8.0 → 补齐「带走」与地图动机）

**现状：**出题 → 策展 → 序章 → 阅读 → 地图 → 导出闭环在；地图是子视图。  
**缺口：**MDX 仅有 API；PDF 实质是浏览器打印；长文篇幅随馆藏波动。

**建议：**

1. **【可施工 · 文档已对齐】** 导出主推 PDF/EPUB；不把 MDX 放首屏。
2. **【可施工】** 地图入口改动机文案（「看本章在街上的位置」）。
3. **【可持续优化】** 长文质量优先：polish/Gate/prompt 与红队迭代，不是一次 PR。
4. **【可施工】** degraded 横幅文案再磨一句「可读但未完整过检」（结构已有）。

**可验收：**从 Brief 到导出，不依赖演示线也能走通一次真实策展。

---

## 4. 可信与溯源工程（8.5 → 从字段门到事实门）

**现状：**A–E 分级、句级出处、Gate、反方策展、失败不灌假数据——主护城河。  
**缺口：**Gate 仍偏字段/套话；反方意见有时存在感弱；句级溯源覆盖不稳定。

**建议：**

1. **【可持续优化】** Gate 升级到事实门（数字/人名/年份对齐）——多轮。
2. **【可施工】** 跋「策展留白」固定渲染 `curator_review` 1–3 条；空则写「本轮无重大异议」。
3. **【可施工 + 数据】** 演示线每章 ≥3 可点出处：先查 fixtures，缺则补包；UI 已有句级组件。
4. **【可施工】** 置信度中文标签：`SentenceProvenance` 把 A/B/C 映射为「馆藏一手 / 可靠二手 / 通识」。

**可验收：**任意演示章点开 3 句，都能落到可理解的出处说明。

---

## 5. 内容品质 / 读感（7.0 → 稳，而不是偶发惊艳）

**现状：**好时像策展散文；差时模板感、热词层薄、人物/事件叠层不足。  
**建议：**

1. **【可持续优化】** 站点分级入线（S/A/B）——要改 plan/evidence 规则 + 数据。
2. **【可持续优化】** 白名单 buri 持续补核心区。
3. **【可施工】** Loading 旁白读 `/v1/health` 热词 `updated_at`，轻提示「当代口吻词库更新于 ××」。
4. **【可持续优化】** 写作规格 + 红队抽检节奏。

**可验收：**连续 5 次真实策展，至少 4 次无「空泛抒情无出处」红队命中。

---

## 6. 交互与等待体验（6.5 → 优先诚实等待，再谈加速）

**现状：**已取消润色未完成时的提前呈现；用户只看进度条，整本完成后再翻开。  
**代价：**等待更长，但不再「半成品抢戏」。

**建议：**

1. **【可施工 · 已做】** 保持「做完再呈现」。
2. **【可施工 · 已做 / 可微调】** SSE 真进度；旁白与 `stage` 对齐可再扫一轮文案。
3. **【可施工 · 暂缓】** 流式重开仅当产品改口；需 feature flag，默认关。
4. **【可施工】** Brief：演示按钮旁注「冻结包 · 秒开」；开始策展旁注「完整策展通常需要数分钟」。

**可验收：**真策展过程中不出现可翻的半成品书页；阶段旁白与后端 stage 一致。

---

## 7. 账号与自有模型（7.0 → 防误填、可理解）

**现状：**游客可策展；登录 / 验证 / 模型配置可用。  
**曾出问题：**浏览器把登录邮箱/密码填进模型表单；「BYOK」用户不懂。

**建议：**

1. **【可施工 · 已做】** 打开/点选回填上方填写栏。
2. **【可施工 · 已做】** 防自动填充 +「不是登录密码」。
3. **【可施工 · 已做】** 未配置一句人话；已配置不刷「就绪」标语。
4. **【可施工】** 连通失败：401 / 超时 / 模型名错误 → 固定下一动作短句（可加强现有 testResult）。

**可验收：**新用户不会把登录密码存成模型 Key；保存后重开能看到模型名在填写栏里。  
**注意：**旧 refresh cookie 可能报「用户不存在」——清 cookie 或重登；登录错密应是「邮箱或密码错误」。

## 8. 数据广度（5.5 → 先深后广）

**现状：**上海竞赛优先合理；live 源少，注册表大于真接通。  
**建议：**

1. **【可施工】** 对外一句「深挖上海馆藏」；不写虚高接入数。
2. **【可施工 · 已有】** 未就绪城市「数据准备中」；**【可持续优化】** 下一城开放门槛（白名单+演示线）。
3. **【可持续优化】** buri / amap / OSM 对齐专项。
4. **【可施工 + 数据】** 出处 UI 展示真实来源名（搜韵等）——依赖 provenance 字段是否带 dataset 标签。

**可验收：**产品叙述与 health/providers 列表一致；用户点出处能看到真实来源名。

---

## 9. 工程与可运维（7.5 → 少手工、多自检）

**现状：**健康检查、SSE、CI/红队、隧道部署能跑；发版偏手工。  
**建议：**

1. **【可施工】** 写 `scripts/smoke_sy_realm.sh`：health + demo/wukang + favicon Content-Length + index bundle 哈希打印。
2. **【可持续优化】** 配置回滚手册、密钥轮换演练。
3. **【可持续优化】** 前端契约测加厚。
4. **【可持续优化】** task 失败日志可检索（不对读者倾倒）。

**可验收：**一次发版后 5 分钟内能用 health + 一条演示线确认「活着」。

**现状：**主 README 已改「做完再呈现 / PDF·EPUB / 篇幅随馆藏」。  
**建议：**

1. **【可施工 · 已做】** README 只写点得到的能力。
