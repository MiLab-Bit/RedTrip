# 红鸢 RedTrip · 产品建设性意见

> 依据现状打分后的改进方向。不含「竞赛答辩」「商业化成熟度」。  
> 原则：**先让承诺与体验对齐，再加深护城河；少加口号，多做可验收的一步。**

评分参照（满分 10，供对照）：定位 8.5 · 品牌 8.0 · 主流程 8.0 · 溯源 8.5 · 读感 7.0 · 等待 6.5 · 账号/自有模型 7.0 · 数据广度 5.5 · 工程运维 7.5 · 文档一致 6.0。

---

## 1. 产品定位与差异化（8.5 → 目标稳住并说清）

**现状：**「馆藏取证 + 关系编织 + 可带走的书」差异清楚。  
**风险：**用户仍可能把它理解成「又一个 AI 路线生成器」。

**建议：**

1. **首屏只钉一句话差异**：继续强化「目录给条目，我们给关系」；Brief 区避免出现模型/API/技术词。
2. **把「不做」写进产品边界**：不做实时导航、不做景点点评聚合、不编造无出处史实——用三条「我们不做」降低错误期待。
3. **差异验证场景固定 2 个**：武康线（建筑叠层）、一大—外滩线（通道诚实）——所有对外描述都以这两条为准绳，避免泛化空谈。

**可验收：**任意新用户 10 秒内能复述「和普通路线 App 的一点不同」。

---

## 2. 品牌与视觉气质（8.0 → 克制加强）

**现状：**纸书 + 红鸢气质统一，优于通用 AI 壳。  
**风险：**局部仍出现工程 jargon（曾用 BYOK）、失败页偏运维口吻、favicon/品牌资产易缓存漂移。

**建议：**

1. **用户可见文案零 jargon**：统一用「自有模型 / 你的 API Key / 模型配置」，禁用 BYOK、SSE、Gate 等对内词。
2. **失败页改读者口吻**：说明「未编造故不展示」即可；运维细节收进可展开的「技术说明」。
3. **品牌资产清单**：`favicon.ico` / `favicon.svg` / `apple-touch-icon` / og 图同一套风筝；发版带 `?v=` 或哈希，避免 CDN 旧图标。
4. **红鸢形象保持轻量**：符号与动效服务「纸鸢牵引记忆」，不做成独立 IP 喧宾夺主。

**可验收：**截图抹掉导航后，仍能一眼认出是红鸢而不是别的产品。

---

## 3. 主流程完整度（8.0 → 补齐「带走」与地图动机）

**现状：**出题 → 策展 → 序章 → 阅读 → 地图 → 导出闭环在；地图是子视图。  
**缺口：**MDX 仅有 API；PDF 实质是浏览器打印；长文「每站 8k–10k」与真实产出不稳定。

**建议：**

1. **导出以 UI 已提供的为准**：主推 PDF（打印成书）+ EPUB；MDX 标成「开发者/进阶」，或做入口但不放首屏承诺。
2. **地图入口给一个阅读动机**：例如「本章在街上的位置」而不是抽象「看舆图」——降低「为什么要离开书页」的摩擦。
3. **长文策略改为质量优先**：宁可短而过 Gate、句句可溯，也不要注水长文回退模板；对外文案改为「可走的长散文（篇幅随馆藏厚度变化）」。
4. **降级态要诚实可见**：`degraded` 横幅保留，并说明「可读但未完整过检」。

**可验收：**从 Brief 到导出，不依赖演示线也能走通一次真实策展。

---

## 4. 可信与溯源工程（8.5 → 从字段门到事实门）

**现状：**A–E 分级、句级出处、Gate、反方策展、失败不灌假数据——主护城河。  
**缺口：**Gate 仍偏字段/套话；反方意见有时存在感弱；句级溯源覆盖不稳定。

**建议：**

1. **Gate 升级路径**：套话拦截 → 出处字段齐全 → **事实门**（关键数字/人名/年份与证据卡对齐抽检）。
2. **反方策展人必须「看得见」**：跋里的「策展留白」固定展示 1–3 条可理解的挑刺，空则明确写「本轮无重大异议」。
3. **句级溯源演示线 100%**：武康 / 一大线每章至少 3 处可点出处；常规线设下限（如 factual 句 ≥70% 有对齐）。
4. **置信度对读者可读**：A/B/C 用短中文标签（「馆藏一手 / 可靠二手 / 通识」），避免只抛字母。

**可验收：**任意演示章点开 3 句，都能落到可理解的出处说明。

---

## 5. 内容品质 / 读感（7.0 → 稳，而不是偶发惊艳）

**现状：**好时像策展散文；差时模板感、热词层薄、人物/事件叠层不足。  
**建议：**

1. **站点分级入线**：S/A 才能当叙事主站；B 仅作步行连接且禁止假装有馆藏细节（见品质规划文档）。
2. **白名单 buri 持续补**：核心区覆盖优先于全量铺开；无 buri 不下重叙事。
3. **L3 热词恢复周更**：health 已能标 stale——前端可在策展旁白轻提示「当代口吻词库更新于 ××」。
4. **写作规格收紧**：禁止导游腔命令式堆砌；衔接句必须有史实/人物理由；长度服从证据，不服从字数 KPI。

**可验收：**连续 5 次真实策展，至少 4 次无「空泛抒情无出处」红队命中。

---

## 6. 交互与等待体验（6.5 → 优先诚实等待，再谈加速）

**现状：**已取消润色未完成时的提前呈现；用户只看进度条，整本完成后再翻开。  
**代价：**等待更长，但不再「半成品抢戏」。

**建议：**

1. **保持「做完再呈现」**：这是当前产品选择；进度文案写清阶段（取证 / 抽签定声线 / 润色 / 装订），避免干等无反馈。
2. **进度条只报真实阶段**：继续用 SSE `progress`；禁止假进度冲到 90% 后卡住。
3. **若以后重开流式**：必须「润色完成的章才能进阅读」，禁止未润色模板冒充成书；与现选择互斥时以产品开关明确。
4. **演示线与真策展分流提示**：点演示时标明「冻结包秒开」；真策展标明「通常需要数分钟」。

**可验收：**真策展过程中不出现可翻的半成品书页；阶段旁白与后端 stage 一致。

## 7. 账号与自有模型（7.0 → 防误填、可理解）

**现状：**游客可策展；登录 / 验证 / 模型配置可用。  
**曾出问题：**浏览器把登录邮箱/密码填进模型表单；「BYOK」用户不懂。

**建议：**

1. **模型配置 = 表单回填优先**：已保存项打开即写入上方（供应商、名称、Base URL、模型名）；密钥不回显。
2. **继续防自动填充**：不用登录式 `password` 框；文案写死「供应商 API Key，不是登录密码」。
3. **未配置时一句人话**：提示去右上角「模型配置」；已配置时不刷存在感标语。
4. **连通性失败可读**：超时 / 401 / 模型名错误分颜色短句，给出下一动作（检查 Base URL / Key / 模型名）。

**可验收：**新用户不会把登录密码存成模型 Key；保存后重开能看到模型名在填写栏里。

## 8. 数据广度（5.5 → 先深后广）

**现状：**上海竞赛优先合理；live 源少，注册表大于真接通。  
**建议：**

1. **对外口径改为「深挖上海馆藏」**：不夸「已接 N 家」；展示「已 live / 快照 / 规划中」三栏更诚实。
2. **下一城只在白名单+演示线齐备后开放**：城市选择器对未就绪城市保持「数据准备中」，不要半开通。
3. **坐标与实体对齐**作为数据债专项：同一建筑多源 ID（buri / amap / OSM）对得上，才允许进主站。
4. **搜韵等 live 源做「可见贡献」**：在出处 UI 标来源名，让用户感到不止一家目录。

**可验收：**产品叙述与 health/providers 列表一致；用户点出处能看到真实来源名。

---

## 9. 工程与可运维（7.5 → 少手工、多自检）

**现状：**健康检查、SSE、CI/红队、隧道部署能跑；发版偏手工。  
**建议：**

1. **发版检查单**：web 静态资源 rsync/tar、API 重启、`/v1/health`、演示线 smoke、favicon 体积非占位。
2. **配置外置且可回滚**：SMTP、默认 LLM、Fernet key、隧道——变更记档；密钥轮换有备份路径。
3. **前端测补关键契约**：策展响应 schema、演示包 schema、auth cookie path；Python 侧保持红队。
4. **日志与任务**：策展 task 失败原因可在运维侧检索；不对读者倾倒堆栈。

**可验收：**一次发版后 5 分钟内能用 health + 一条演示线确认「活着」。

---

## 10. 文档与承诺一致（6.0 → 立刻对齐）

**现状：**README 曾写「逐章流式不用干等」「一键 MDX」等，与当前体验不完全一致。  
**建议：**

1. **README 只写用户此刻能点到的能力**；规划中能力放「路线图」或本文档。
2. **长文篇幅、流式阅读、导出格式**三类最易夸大——改为现状描述 + 可选「进行中」。
3. **包内 README / 早期 Doc** 与主 README 冲突时，以主 README + 本文档为准，旧 Doc 加过期注。
4. **每次关掉或打开大能力**（如提前预览）同步改文档，避免答辩/用户按旧说明操作。

**可验收：**按 README 逐步操作，不会撞上「写了但点不到」的功能。

