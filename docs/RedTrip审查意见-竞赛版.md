## 一句话总判

工程完成度明显高于普通黑客松 Demo，**“防幻觉做成工程”这条叙事是真的有代码支撑的**。  
但当前最大风险不是“功能不够”，而是**对外承诺略超前于可核验事实**——评委若抽查 10 分钟，最容易在「28 家数据源 / 红队全绿 / Gate 挡住幻觉 / 句句馆藏」四处翻车。

竞赛策略：**先收缩承诺、坐实已验证机制，再谈扩城与部署。**

## 已验证的加分点（答辩请主打这些）

1. **管线可解释**：`intent → evidence → plan → narrative → polish → gate → review`，不是单次大模型玄学出稿。
2. **年份防编造是硬规则**：润色阶段会拒绝未取证年份（比“提示词别编”更有说服力）。
3. **Gate 维度扎实**：出处 / 避坑字段 / 禁词 / 禁止「步行五分钟当衔接理由」等都有实现。
4. **降级方向总体诚实**：API 已拆除假 demo fixture 硬塞；无 key 时走本地 RAG。
5. **体验完整**：SSE 流式章节、书页阅读、2.5D 舆图、PDF/EPUB 导出、反方策展人（非阻断）。
6. **线上可演示**：`/redtrip/v1/health` 显示 `slc_key_configured=true`、`gate=true`、`whitelist=true`。

## 严重问题（比赛前必须处理）

### 1. 红队当前是红的（会当场翻车）
本地跑 `redteam`：**REDTEAM_FAIL**。  
合法基线用例被新升级的第二人称禁词（如「你站在」）误杀，说明**禁词升级后 fixture/红队未同步**。  
对外再说「红队 12 条全通过」会被演示打脸。

### 2. Gate 失败对外仍像成功
代码里有 `degraded` 状态设计，但成功路径常固定 `status="ok"`、`gate.passed=True`。  
评委一看响应就会问：「门禁到底挡没挡住？」

### 3. 「28 家数据源」经不起打开
线上 `/v1/providers`：共 28，**真正 ready 的只有 2**（上图 live + 搜韵）。  
其余多为 snapshot 占位；`content/partner/` 目录不存在。  
答辩应改口：**已注册 28 / 已接通 2 / 其余待授权落盘**。

### 4. 「馆藏策展」主叙事与数据覆盖脱节
白名单 180 点，**仅 24 点有 buri**，156 点 `buri=None`。  
大量路线会走 amap/OSM RAG，本质是「地标库策展」，不是「馆藏交叉印证」。  
这是评委最容易戳穿的产品诚实度问题。

### 5. G4「溯源 100%」偏字段完备，不偏正文忠实
当前更像「layer 有没有 record_id」，不是「润色句子是否忠实于证据」。  
句子级 provenance 在线上常为空，前端角标难以演示。

## 拿奖优先级（按投入产出）

### P0（本周必须，答辩保底）
1. **修好红队并接入 CI**（pytest + redteam），再对外讲「可信」。
2. **API 状态诚实化**：模板回退 / Gate 失败 → `degraded`，禁止伪装成功。
3. **改对外话术**：28 源、每站八千字、句句馆藏——全部改成可核验表述。
4. **演示脚本与 FSM 同版本**；预热缓存；准备 90 秒录屏备援。
5. **StopPanel 展示 pitfalls**；挂上时间轴或分层证据列，服务「关系」口号。

### P1（显著加分）
1. 核心风貌区补 buri（先把演示线 6–8 站做实馆藏 URI）。
2. 接通 `sentence_provenance`，让句末角标可点。
3. 竞赛模式 Brief：默认只留「和谁 / 多久 / 调性 / 从哪走」，多城折叠。
4. 健康面板修正 ready/ingested 口径，避免注水观感。

### P2（可后置，别在答辩前分心）
- 新域名、完整上线、多城铺开、展讯实时、GraphRAG、MDX 按钮  
这些不决定能不能讲清「目录给条目，我们给关系」。

## 建议的 90 秒答辩结构

1. **定位**：别人给线路，我们用馆藏策展览。  
2. **现场出题**：2 人 / 90 分钟 / 轻社交 / 一大周边。  
3. **指关系**：打开第 1 站，讲 building × event × person，不是 POI 清单。  
4. **指可信**：点出处；强调「找不到就写未收录 / 未取证年份会被拒」。  
5. **收束金句**：目录给条目，我们给关系。

禁语：一键生成、28 家全接通、全市建筑库、每站必有万字馆藏原文。

## 结论

RedTrip **已经具备拿奖的技术骨架**。  
现在要做的不是继续堆功能，而是把「可被抽查的诚实」做到位：红队变绿、状态变真、数据口径变准、演示路径变稳。  

先质量，后部署——这个顺序是对的。
