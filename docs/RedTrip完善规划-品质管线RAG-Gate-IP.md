# 红鸢 RedTrip · 内容品质 / 管线 / 三层 RAG / Gate 完善规划

> 原则：先可核验，再变好看；IP 强化服务策展可信，不抢馆藏主角。  
> 范围：内容品质 · 数据处理管线 · 三层 Agentic RAG · Gate · 美学/交互/视觉符号/红鸢形象

---

## 0. 总判断

| 维度 | 现状 | 要不要大力加码 |
|---|---|---|
| 内容品质 | 骨架强，馆藏覆盖与实体层薄 | **必须大力优化**（冲奖主战场） |
| 数据处理管线 | 分解清晰，多处半接线 | **系统补齐**，别再加第四条平行管线 |
| 三层 Agentic RAG | L1/L2/L3 概念已冻结；L3 半死、L1 偏地标库 | **按层专项升级** |
| Gate | 已能拦一批硬伤；红队刚修绿 | **从「字段门禁」升级到「事实门禁」** |
| 美学/交互 | 海派纸书系统已锁，可用 | **加强，但是「克制加强」** |
| 红鸢人物 IP | 几乎空白（只有隐喻与 agent 名） | **要做，但是轻量、可识别、不喧宾夺主** |

一句话：  
**品质与可核验性决定能不能拿奖；红鸢形象决定好不好记。先把证据做实，再用一个克制的纸鸢形象把品牌钉死。**

## 1. 内容品质优化规划

### 1.1 品质目标（可验收）

| 指标 | 当前（约） | 目标 |
|---|---|---|
| 演示线每站可点上图 URI | 竞赛线已补齐 6 站 | 保持；扩展到 2 条备用线 |
| 白名单 buri 覆盖率 | ~13%（24/180） | 核心区 ≥60%；全量 ≥35% |
| 路线含 building+person/event 多重身份 | 常 warn | 首过率 ≥90%（演示线 100%） |
| 每路线非通识细节 | 不稳定 | ≥3 条，且均可溯 |
| 套话出现率 | 未量化 | 0%（Gate + eval） |
| 事实幻觉率（抽检） | 未量化 | <2% |
| Gate 一次过率 | 未量化 | >95%（模板回退不算一次过） |
| 句子溯源可演示率 | 常空 | 演示线 100%；常规路线 ≥70% factual 对齐 |

### 1.2 内容分层（别再用同一标准要求所有点）

```
S 级（竞赛核心）：有 buri + 人物/事件层 + 可走避坑 + 句级溯源
A 级（可入线）：有 buri 或可靠 landmark-facts；至少双重身份
B 级（仅地理辅助）：amap/OSM，只可作步行连接，不可充当「馆藏主角」
C 级（噪声）：标识牌/轮渡口/打卡位 → 过滤，永不入叙事主链
```

规则：  
- 叙事主站必须 ≥A  
- B 级最多作过渡，文案禁止假装有馆藏细节  
- envelope meta 显式标注每站 `evidence_channel: slc | landmark | osm`

### 1.3 内容生产节奏（可持续）

| 频率 | 动作 |
|---|---|
| 每周二 | L3 热词更新（恢复周更） |
| 每周 | 补 5–10 个 buri 映射 + 1 栋楼的人物/事件层 |
| 每次发版前 | 跑红队 + eval 抽检 3 条真实策展 |
| 赛前冻结 | 锁定 2 条演示线（主+备），禁止临时改口径 |

### 1.4 叙事品质规格（写作侧）

- 故事卡：第二人称允许；禁止导游腔命令式堆砌（essay 更严）  
- 衔接句：100% 史实/人物理由（R19）  
- 长散文：有则优，无则短而准——**宁可 1200 字过 Gate，不要 8000 字注水回退模板**  
- 反方策展人产出必须在书末「策展留白」可见（现在几乎不展示）

## 2. 数据处理管线优化规划

### 2.1 目标形态（在现有管线上增强，不重写）

```
intent
 → evidence（L1，通道分级）
 → entity_enrich（人物/事件/展讯）
 → join（多重身份排序）
 → plan（+ act 四段节奏）
 → voice（L2 抽签 + L3 热词）
 → narrative / polish
 → sentence_provenance（升为可阻断或强制改写）
 → gate
 → review（反方，非阻断但必展示）
 → package（web / pdf / epub）
```

### 2.2 分阶段工作包

#### Phase D1 · 数据诚实与通道标注（最高优先级）
1. 每站写入 `evidence_channel` / `buri` / `confidence_grade`  
2. health/providers：live 必须真实 probe；禁止「注册=接通」  
3. B 级站自动降权：不可单独构成主题锚点  
4. 白名单去重（已发现同 id 污染「水杉夜魅」类脏数据）

#### Phase D2 · 实体层扩充
1. 扩展 `landmark-facts`：从外滩 6 条 → 梧桐/一大/外滩 80+ 条精品  
2. SLC landmark-facts / building.relation 批量补 person/event  
3. Join 策略：无 person/event 的路线 Gate 从 warn → 演示模式 blocker  
4. 展讯：先 `exhibitions.json` 占位，再接实时

#### Phase D3 · 规划与节奏
1. `plan.act ∈ {prologue, focus, transit, epilogue}`  
2. 前端 BookShell / Map 按 act 高亮与 flyTo  
3. 与现有 `narrative_arc`（Hook/Contrast/Reveal…）对齐，避免两套节奏语言

#### Phase D4 · 评估闭环
1. 建 `eval/`：套话重叠率、年份幻觉、出处覆盖、一次过率  
2. 每次 polish 变更必须跑 eval 基线对比  
3. e2e 样本入库 `content/e2e/`，答辩可展示

## 3. 三层 Agentic RAG 优化规划

### 冻结规则（保持）
- L1：史实唯一来源  
- L2/L3：只改口吻，不增史实  
- 失败回退模板，不硬编

### 3.1 L1 Evidence RAG（最该砸资源）

| 优化项 | 做法 | 验收 |
|---|---|---|
| 馆藏优先 | buri 命中路径加权；无 buri 不得自称「馆藏策展完成」 | meta 诚实 |
| 检索质量 | 场景/时段/类别预筛 + 噪声黑名单持续扩 | 噪声入线 <5% |
| 证据打包 | 每站 EvidencePack：claims、grade A–E、URI、摘录 | 前端可展开 |
| 跨库 join | building 主键串 person/event；缺维标明「暂无」 | 演示线三重可见 |
| 缓存 | 指纹缓存保留；degraded 不入成功缓存 | 已有，保持 |

### 3.2 L2 Lexicon lottery（红鸢读法）

| 优化项 | 做法 |
|---|---|
| 词库质量 | 按调性（文艺/轻社交/硬核）分桶审校；剔除口号体 |
| 可解释 | 前端展示「本次红鸢抽签：情绪×风格×节奏」一枚印章条 |
| 约束 | 抽签结果写入 assumptions；润色 prompt 强制「不得借读法新增年份」 |
| 多样性 | 同槽位连续三次抽签不得完全相同（答辩演示可复现种子） |

### 3.3 L3 Hotword RAG（当代口吻）

| 优化项 | 做法 |
|---|---|
| 恢复周更 | 每周二流水线 + CI 检查 `latest.json` 新鲜度（>14 天告警） |
| 景点对齐 | 热词必须能挂到 whitelist/scene，否则不进 VoicePack |
| 安全 | 热词不得覆盖史实句；只进 connective / 当代提示 |
| 降级 | 无热词时明确「本周无当代口吻层」，不要静默假装有 |

### 3.4 「Agentic」要什么、不要什么
- **要**：分层职责、可观测中间态、失败可解释  
- **不要**：再造 4 个空 Agent 改名；不要上 Neo4j GraphRAG（单城体量不值得）  
- **关系图**：继续用轻量 EvidenceGraph + 前端 RelationGraph 即可

## 4. Gate 优化规划

### 4.1 从字段门禁 → 事实门禁

| 级别 | 规则 | 动作 |
|---|---|---|
| Blocker | 缺 source、假 exact、纯物理衔接、效率/口号禁词、essay 导游腔 | 不通过 → degraded |
| Blocker（新） | 润色正文出现未取证年份（已有 polish 拒绝，Gate 再兜底） | blocker |
| Blocker（演示模式） | 主站无 person/event | blocker |
| Warn→Blocker（渐进） | 句子 factual 未对齐超过阈值 | 先 warn，赛前升 blocker |
| Warn | 反怀旧套话、C 级无归属词 | warn + 反方评审引用 |

### 4.2 红队扩充（B4）
新增用例：
1. 噪声 POI 入线必须拦/降级  
2. 无实体层路线（仅 building）  
3. 句子无溯源却声称可核  
4. providers 注水话术（文案层）  
5. degraded 必须 `gate.passed=false`

### 4.3 Gate 与产品话术对齐
- 对外只说「Gate 能拦的」：缺出处、禁词、物理衔接、未取证年份  
- 不说「已消灭一切幻觉」  
- 一次过率进面板，给评委看数字而不是口号

## 5. 美学 · 交互 · 视觉符号 · 红鸢 IP —— 要不要加强？

### 5.1 结论（直接回答你）

**要加强，而且红鸢人物形象值得做——但必须克制，做成「策展人的纸鸢使者」，不要做成卡通吉祥物抢戏。**

理由：
1. **现在品牌信号偏弱**：代码里 agent 叫红鸢，首屏却常常是 `RedTrip` 英文；logo 图在文档里，出题页没用。评委记不住「谁」在策展。  
2. **海派纸书美学已经很好**：六色、宣纸、书壳、朱砂——这是差异化资产。IP 应寄生在这套语言上，而不是另起一套潮玩风。  
3. **竞赛语境是图书馆**：过度吉祥物化会显得轻；一个简练的「纸鸢/红鸢剪影 + 印章人格」更像文化产品。  
4. **内容品质仍是主矛盾**：没有 buri 的路线，再好看的 IP 也救不了抽查。

### 5.2 IP 定位（建议拍板）

**红鸢不是导游，是「牵线的城市记忆信使」。**

| 属性 | 设定 |
|---|---|
| 物种隐喻 | 纸鸢（可放飞、可收回、线在手中） |
| 性格 | 克制、好奇、敢说「暂无数据支撑」 |
| 不做什么 | 不喊口号、不卖货、不卖萌过度 |
| 视觉 | 朱红线 + 墨色鸢骨；可一枚印章、一个侧影、一次振翼动效 |
| 出现场景 | 出题页伴读、Loading 牵线、抽签揭示、出处角标旁的小印 |

**三件套就够（赛前）：**
1. **红鸢侧影符号**（SVG，单色可印）  
2. **朱砂「鸢」印**（抽签/过 Gate 时盖一下）  
3. **一句人格旁白**（例如 Loading：「红鸢去馆藏里取证，不会替馆藏说话。」）

**不做（赛前）：**
- 全套立绘表情包  
- 3D 形象 / Live2D  
- 故事线独立角色剧  
- 紫色霓虹潮玩风

### 5.3 美学与交互加强清单（克制版）

#### 视觉符号
- 首屏品牌改回 **「红鸢」为主、RedTrip 为副**  
- Logo/侧影进入 Brief 与书脊  
- 出处角标统一为「鸢印 + 数字」  
- 关系图节点沿用海派六色，不另开色板

#### 交互
- Loading：三阶段文案对齐 L1/L2/L3（取证→抽签→当代口吻）  
- 抽签结果可视化（本次读法）  
- 反方策展「留白」附录可翻到  
- 降级态用朱砂条提示，不恐吓、不假装成功

#### 动效（2–3 个就够）
1. 纸鸢线抽出（Loading）  
2. 印章落下（抽签/过 Gate）  
3. 书页翻页（已有则打磨）

### 5.4 IP 与内容的正确关系

```
馆藏证据（主角）
    ↑ 红鸢只牵线
读者行走
```

红鸢可以「在场」，但不能「代替证据说话」。  
任何 IP 文案若引入新史实 → Gate 直接杀。

## 6. 总路线图（完善优先序）

### P0（冲奖生命线）
1. buri/实体层扩充（核心区）  
2. L1 通道诚实标注 + 白名单去重  
3. Gate 事实向增强 + 红队扩真实失败模式  
4. 句子溯源演示稳定  
5. 演示线冻结 + 反方评审可见  

### P1（差异化拉满）
1. L3 周更恢复  
2. plan.act + 地图/书页节奏联动  
3. eval 量化面板  
4. 红鸢三件套 IP（侧影/印章/旁白）  
5. 展讯占位  

### P2（完整上线期再做）
1. 多城内容深化（不是只加 OSM）  
2. 账号/BYOK 体验打磨  
3. 新域名与传播物料  
4. 若仍要「图谱感」：增强 EvidenceGraph 可视化，不上 Neo4j

## 7. 对你问题的直接答案

1. **内容品质、管线、三层 RAG、Gate：都需要优化**——而且应按本文分层推进，重点砸 L1 实体与 Gate 事实化，而不是再堆模型。  
2. **美学和交互：需要加强，但是克制加强**——把现有海派纸书语言用满，补品牌主名「红鸢」、出处符号、Loading/抽签反馈。  
3. **红鸢人物形象：值得做**——做成「纸鸢信使」轻 IP，三件套即可；不要做成喧宾夺主的吉祥物。  
4. **完善的标准**：评委 10 分钟抽查仍站得住——URI 可点、关系看得见、失败说真话、红鸢记得住。
