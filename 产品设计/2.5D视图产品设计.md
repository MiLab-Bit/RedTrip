# 2.5D 视图产品设计：如何做到"好看且准确"

> 适用：红色研学 / 城市记忆路线的空间呈现层。
> 目标：既不是"地图查询工具"，也不是"抗日神剧式虚构场景"，而是**地理可信、海派统一、可策展**的意象化 2.5D。

---

## 1. 先定义这两个词在这个产品里是什么

**"准确" ≠ 照片级实景三维。** 实景三维上海 / 测绘院意象框架城市不可直接商用（见数据源选型表），追逐它会卡死。本产品的"准确"定义为四点：
1. **地理落位正确**——建筑在真实坐标上，节点相对位置、距离、朝向可信。
2. **建筑轮廓真实**——挤出的是真实 footprint 多边形，不是凭空画的方块。
3. **历史标注有据**——名称、年代、事件来自开放数据，不臆造。
4. **风格化诚实**——高度缺失、细节简化的地方明确标"示意"，不假装精确。

**"好看" = 统一海派意象**：克制配色、插画/明信片质感、可读的路线叙事，而非花哨特效。

> 一句话：**准确靠真实数据，好看靠一致风格化。两层解耦，才不会互相将就。**

---

## 2. 准确性从哪来（数据基座，复用选型表）

| 用途 | 数据源 | 提供什么 | 准确性边界 |
|------|--------|----------|------------|
| 建筑轮廓 | **OpenStreetMap** `building` 多边形（Overpass API） | 真实足迹 + 层数 `building:levels` | 高度常缺，用 `levels×3m` 估算；老城里弄可能合并 |
| POI / 路网 | **天地图·上海**（Key） | 定位、路径规划 | 商用授权 ⚠️ 待确认 |
| 历史地址 / 事件 | **上海图书馆 MCP** `slc_building` / `slc_red_event` | 叙事、年代、红色线索 | 来自真实库，优先采信 |
| 地形（可选） | 天地图 terrain | 高程 | 非必需，路线场景可省 |

**关键判断**：OSM 是本项目唯一"开放且几何真实"的建筑源；天地图补定位与路网；图书馆 MCP 补内容。三者合一，准确性有根。

---

## 3. 好看从哪来（美学层，R3F 实现）

### 3.1 海派配色（固定 6 色，超出即违规）
| 角色 | 色值 | 用途 |
|------|------|------|
| 墨（建筑暗面） | `#33333A` | 主体阴影面 |
| 赭石（老墙暖面） | `#B9824F` | 石库门砖墙、暖光面 |
| 青灰（辅建筑） | `#7C8A8D` | 背景建筑、统一基调 |
| 米白（纸感高光） | `#EDE4D3` | 顶面、卡片底 |
| 朱（重点标记） | `#A8322A` | 路线节点、红色点 |
| 宣纸天空 | `#F2EBDD` | 背景、雾 |

### 3.2 材质与光照
- **Flat shading + toon outline**：无 PBR，插画边线（明信片感），不是写实渲染。
- **低角度暖光** `#FFE8C8` + 柔和阴影 + 轻雾，制造"黄昏里弄"氛围。
- **相机**：等距 / 低仰角（俯角 ~50°，FOV 35），可旋转缩放，不做自由飞行。

### 3.3 字体与路线
- 节点标签用海派衬线（如 思源宋体 / 标宋），不用无衬线抢戏。
- 路线用**缎带式 ribbon** 连接节点，节点上挂卡片（见 §6 契约映射）。

---

## 4. 技术管线（三层解耦）

```
[真实数据层]
  OSM building footprints (Overpass)  ──┐
  天地图 POI / 路网 (Key)              ──┼─→ GeoJSON：投影→简化→合并→裁走廊
  上海图书馆 slc_building (历史地址)   ──┘
          │
          ▼
[几何构建层]
  footprints → 按 levels×3m 挤出 → mesh
  路线节点 → 坐标定位 → marker
  高度缺失 → 标 "示意高度" 字段
          │
          ▼
[美学渲染层]  (React Three Fiber + Drei)
  海派 palette + flat shading + toon outline
  + 低角度暖光 + 软阴影 + 轻雾
  + 节点卡片(scene block) + 路线 ribbon
          │
          ▼
交付：2.5D 场景页 / 路线卡片 / 研学手册空间页
```

---

## 5. 英雄节点策略（策展质感的关键）

一条路线（如"石库门红色线"）只把 **2–3 个核心遗产点**做重：
- 真实 footprint 挤出 + 轻量门头 / 屋顶风格化（明确标"示意"）。
- 挂 `scene` 卡片（来自 v2 输出契约）：1920 年代此处样貌、谁在此活动、今日为何值得看。
- 其余走廊建筑统一低矮挤出，不抢戏、不编造。

> 这样"准确"由足迹保证，"策展感"由英雄节点 + 叙事保证，二者不冲突。

---

## 6. 准确性护栏（防编造 / 防神剧化）

1. 不凭空造建筑；视图里没有的足迹不出现。
2. 高度缺失一律标"示意高度"，不在 UI 伪装成实测。
3. 历史注记只来自 MCP，标注来源（OSM / 天地图 / 上海图书馆）。
4. 视图角标固定显示「数据来源：OSM · 天地图 · 上海图书馆」。

---

## 7. 性能与范围

- **只渲染路线走廊** footprints，视口外裁剪；中心城区不全量加载。
- OSM 原始多边形需简化（Douglas–Peucker）后再挤出，控顶点数。
- 移动端降级：关软阴影、降 DPR、ribbon 改线段。

---

## 8. 待验证 / 风险

| 项 | 风险 | 对策 |
|----|------|------|
| OSM 老城轮廓完整度 | 石库门里弄可能缺高度 / 被合并 | 抽样验证一大会址周边；缺则走英雄节点策略 |
| 天地图 Key 商用 | ⚠️ 未确认 | 原型用个人 Key；发布前复核条款 |
| 真 3D vs 伪 2.5D | 纠结会拖慢 | **定调：extruded flat（R3F）**，可交互、准确、可量产 |
| 风格化越界 | 变"游戏地图" | 6 色锁死 + toon outline，评审前人工过一遍 |

---

## 9. 与 v2 输出契约的对应

| v2 block | 2.5D 视图落点 |
|----------|---------------|
| `route_node` | 路线 ribbon + 节点 marker + 时长标注 |
| `scene` | 英雄节点卡片（3D 旁挂 2D 卡） |
| `card` | 城市记忆卡片（可叠在视图角落） |
| `manual_page` | 研学手册"空间叙事页"配该视图截图 |

---

## 结论

好看且准确，**不是同一个动作，而是两个动作**：用 OSM + 天地图 + 图书馆 MCP 拿到真实几何与内容，再用一套锁死的海派风格化把它"翻译"成意象。不追实景三维、不编建筑、不神剧化——这就是本产品 2.5D 视图的设计底线。
