## 1. 产品定位与差异化

### 1.1 主定位

> **别人给你一条红色线路；我们用上海图书馆的真实馆藏，为你策一场只属于你的城市展览。**

### 1.2 差异化的唯一正确表述：引擎 vs 线路

上历博「弄堂里的秘密斗争」已上线高度雷同的 Citywalk（9 点位、小程序、打卡解锁、结束生成探寻报告），**原"可分享生成物 / 反说教"两个差异点已被占用**。因此差异化重心整体挪到产能维度：

| | 对手（手工线路） | 我们（策展引擎） |
|---|---|---|
| 交付物 | 1 条打磨一年的固定线 | 从 612 处资源实时生成 N 条线 |
| 产能 | 线性，受领队数约束（3 年千人量级） | **非线性，边际成本≈0** |
| 成行门槛 | 团组预约 + 固定场次 + 需抢名额 | **1 人成行 · 当天即起**（此格仍空） |
| 内容深度 | 同策展级 | 同策展级（对外口径，rubric 双轴精确定级见 §9.1） |

> **深度口径一致性说明**：对外统一表述为「同属策展级、差异在产能」，禁写"我们深度更高"。内部 rubric 双轴（竞析 v2 / 数析附录）将深度拆为 A 轴（叙事深度，上历博 A4 / 我方目标 A5）与 B 轴（交付形态，上历博 B0 / 我方目标 B2），A5 成立与否待 S0-4 实测，详见 §9.1。

**全员统一口径三条（写入所有对外材料）**：
1. **禁写"我们深度更高"** —— 对外口径与上历博同属策展级，领先只在产能。深度分级（A 轴）：1 播报问答 / 2 索引打卡 / 3 单馆深讲 / 4 跨点策展 / 5 跨库史料缝合+逐句可溯源。
2. **主威胁是沪小游，不是上历博** —— 上历博免费**但稀缺**（有产能上限）；沪小游免费 + 无限供给 + 官方背书 + 已有 citywalk 与红色旅游类目，且**已具备生成物**（AI 游记，B 轴有产物），但叙事深度停 1–2（A2 / B1）；**真实风险是它迭代补深度，窗口以季度计**。
3. **上历博是首选客户，不是对手** —— 无商业化动机、连续 3 年撞产能天花板、有预算渠道（"历小博"机器人已入驻文创店，说明馆方数字化意愿与预算均在）。BD 走**双线**：馆方（使用方/内容方）+ 宣传口·组织口（预算方/决策方）。

### 1.3 机制解释（最难被反驳的一段，建议直接进方案与答辩）

> 上历博的免费，是公共财政补贴掉了真人成本——**成本没有消失，只是没向用户收**。所以它能免费，却卡在千人量级：**补贴能覆盖价格，覆盖不了产能。** 这一格空着不是"没人想到"，而是"过去做高深度必须堆人"。我们是唯一能非线性扩产的形态。

### 1.4 ⚠️ 自洽性铁律（本文档最高约束）

> **若为拿到 150–199 元客单价而配真人领队，我们就变成了上历博：回落高深度低产能象限，亲手放弃非线性扩张——而那正是我们全部论证的基础。**

**因此："v1 不配真人领队"是产品级铁律，不是资源约束。** 任何以"提升客单价"为由引入真人环节的提案，必须先推翻本节论证。

### 1.5 三受众话术

| 受众 | 一句话 |
|---|---|
| 年轻人 | "这栋楼你路过一百次。90 分钟，我用上图的原始档案告诉你它经历过什么——每句话都能点开看出处。" |
| 竞赛评委 | "把上图开放数据从资源目录变成叙事图谱：跨数据集做实体关联并生成式策展，事实句 100% 可回溯到数据集/字段/记录。" |
| 官方 / B 端 | "我们不抢流量，做上游内容供给层：把资源目录转成年轻人可消费的叙事单元，B 端批量出线路，C 端做品牌。" |

**Battle-card（终版）**
> 「上图 612 处红色资源 × AI 策展引擎：过去做一条好线路要一年、一场只能带 15 人；现在为每个人现生成一条，每句话都查得到出处。」

**抗反驳一句话（建议进演示话术，竞析 v2 / 数析附录）**
> 「它有 6.2 万条**目录条目**，我们做的是**条目之间的关系**——目录再多也生成不出『一栋楼的多重人生』。」（抗反驳强度高于任何"我们更深"的表述）

必答问题：
- **"上历博不是已经做了吗？"** → "做了，做得很好——这恰恰证明需求真实、模式跑通。但它 3 年只服务了千人量级，因为每条线路要人工策展、每场只能带 15 人、还得抢名额。我们不替代它，我们把它的策展能力变成引擎。"
- **"和沪小游什么区别？"** → "它告诉你去哪，我们告诉你为什么值得去、看什么——它给你 6.2 万条目录，我们给你目录之间的关系。"
- **"和 9.9 元 AI 讲解什么区别？"** → "不是讲解器，是策展人——有线索、有结构、有作品产出。"
- **"怎么赚钱？"** → "主要赚 B 端的钱。C 端先做漏斗不急变现——纯内容付费这个市场还没有过成功观测，我们会用一次轻履约定价实验去验证，而不是拍脑袋定价。"

## 2. 目标用户与典型场景

### 2.1 三个 C 端 persona

| Persona | 画像 | 最短说服路径 | v1 必须给到 |
|---|---|---|---|
| **A 梧桐区文艺策展人** | 22–28 女，传播源头 | 审美调性统一 + 独家信息 | 统一视觉的路线长图、可直接发布的卡片 |
| **B 硬核考据党** | 20–30，可信度背书者 | 每条事实可展开原文与出处 | 溯源能力、跨库时间轴、"暂无收录"诚实标注 |
| **C 情侣闺蜜轻社交** | 21–30，2 人同行 | 90 分钟轻量 + 结尾仪式感 + **红色不尴尬** | 双人 90 分钟档、去说教化文案、收尾同框仪式 |

> **C 是最难一关**：文案层面全局禁用口号式表述与表态引导，改用"具体细节 + 人的处境"。写入文案红线，由门禁强制。

### 2.2 B 端客户（主要收入来源）

**馆方 / 场馆教育部门**（使用方、内容方，痛点=产能天花板）+ **宣传口 · 组织口**（预算方、决策方）。核心需求：把一条线路的人工策展成本，变成可批量产出的引擎。

> **市场定位提示（D10 触发降级）**：本提交物以竞赛作品身份提交，B 端付款人（谁签字 / 走哪笔预算 / 单价与批量）尚未指名；B 端闭环作为后续开发路径的验证目标，不构成本提交物的交付承诺。

### 2.3 用户故事（Given / When / Then）

**US-1（A · 素材与调性）**
Given 我是内容创作者，周六下午空 2 小时，想要"梧桐区 + 老洋房"调性
When 我填完出题并生成路线
Then 我得到 6 点位路线图与配套卡片，视觉风格统一，可直接发布，无需二次加工

**US-2（B · 溯源）**
Given 我看到卡片写"这栋楼 1927 年曾是某机关联络点"
When 我点开该句旁的来源角标
Then 展开原文片段与数据集出处；若该细节无收录，明确显示"暂无数据支撑"，而不是给我一段听起来合理的话

**US-3（C · 双人轻社交）**
Given 我和对象当天起意，只想走 90 分钟且不想被说教
When 我选择"2 人 / 轻松 / 90 分钟"
Then 得到 5 点位路线，文案无口号式表述，结尾给出一个同框机位与纪念卡，全程可随时结束

**US-4（护城河演示 · 跨库叙事）**
Given 我对某栋建筑感兴趣
When 我切换到该点位的时间轴
Then 看到同一坐标上由不同数据集缝合出的多重身份，每层标注来源
> 本条的可达层数取决于 S0-4 实测结果，若为两重则演示口径同步下调为「一栋楼的两重人生」（见 §9.3 / §11 D1，已拍板）。

**US-5（可懂 · 策展说明）**
Given 我拿到一条 6 点位路线
When 我阅读开篇策展词与点位之间的衔接
Then 我能回答"为什么是这几个点、它们之间是什么关系"；衔接理由是史实线索，**不是"步行 5 分钟可达"这类物理理由**

**US-6（B 端 · 批量供给）**
Given 我是场馆教育项目负责人，需要为一批党团组织准备主题线路
When 我指定主题与时长批量生成
Then 得到多份结构一致、可打印、事实可溯的线路与讲义草案

**US-7（内部 · 质检门禁）**
Given Agent 生成了一版路线
When 进入交付前门禁
Then 自动校验通过才放行；任一发布阻断项 FAIL 则拦截并回写原因，不向用户输出

## 3. 核心概念与信息架构

### 3.1 五个核心概念（全团队统一词汇）

| 概念 | 定义 | 为什么它重要 |
|---|---|---|
| **跨库关系图谱** | 以建筑为主键，把红色事件、历史纪年、诗词等不同数据集的记录关联到同一空间对象上，生成"关系"而非"条目" | 单馆数据结构做不出，是不可复制优势的来源（沪小游只有 6.2 万条目录条目，结构上产不出"条目之间的关系"） |
| **策展路线** | 5–8 个点位 + 一条贯穿的叙事线索 + 点位间的史实衔接理由 | 区别于"点位列表"的唯一标志 |
| **取证铁律** | 任何事实性陈述必须先取证再表述；无据则明写"暂无数据支撑"，**不补编** | 品类信任赤字的解法（66% 游客会二次验证；AI 旅游助手错误信息投诉占比 27%） |
| **2.5D 城市记忆地图** | 地理可信 + 海派统一 + 可策展的意象化视图。**准确 ≠ 照片级实景**，缺失处诚实标"示意" | 代际视觉差 + 诚实边界 |
| **出题式输入（6 槽位）** | 人群 · 场景（含出发点）· 时长 · 风格调性 · 交付形态 · **同行结构** | 把"报名"反转为"出题"，是去"被组织"感的入口机制 |

> 6 槽位 = 既有 5 槽位 + **同行结构**（独自 / 2 人 / 3–4 人小团体）。瑞思发现 2–4 人小团体是最大供给空档，必须成为一等输入。
> **补全协议**：6 项中缺 ≥3 项才向用户追问 **1 个问题**；否则按默认假设（成人 · 半天 · 城市记忆 · 轻松版）执行，并在开头**显式声明该假设**。

### 3.2 主流程（五步）

```
① 出题（≤30s，最多 1 问）
   ↓
② 策展（取证 → 跨库缝合 → 选点排序 → 生成叙事与策展说明）
   ↓
③ 2.5D 城市记忆地图（含序号、连线、步行距离与预计耗时）
   ↓
④ 漫步（点位卡片，可断可续，任意点终止均有收尾）
   ↓
⑤ 收尾（纪念卡 / 素材导出）
```

### 3.3 内容分层（决定谁负责什么）

| 层 | 内容 | 来源 | v1 状态 |
|---|---|---|---|
| **事实层** | 事件、人物、年代、原文片段、出处 | 上图开放数据 | 依赖 S0 打通 |
| **地理层** | 点位坐标、步行距离、开放时间、可入内、是否需预约 | **v1 走 30 点位人工核录资产（R-20）**；S1 起视实测结果切换为数据源驱动 | **与外部审批解耦** |
| **叙事层** | 策展词、衔接理由、故事卡、年龄对照句、机位文案 | 生成，但只引用不编造 | v1 交付 |
| **表现层** | 地图渲染、卡片模板、导出成品 | 前端统一模板 | v1 交付示意图版 |

> **解耦原则**：准确性来自真实数据，好看来自一致风格化，两层不互相将就。
> **v1 关键设计决定**：把地理层从外部数据源上摘下来，改由内部资产供给——这是 v1 不被 S0 结果阻塞的唯一原因。

## 5. 取证与质量体系

### 5.1 取证铁律（写入生成阶段硬约束）

1. 任何事实性陈述必须先取证再表述，**未取到即不得断言**。
2. 输出必须标注出处（数据集 + 记录标识），出处需可核对。
3. 取证为空或不确定时，明确写"暂无数据支撑"，**不补编、不推测、不用合理想象填空**。
4. 不得把取到的数据当装饰、实际内容仍靠臆测。

## 6. 美学与体验规范

### 6.1 视觉

- **海派 6 色锁死**：墨（建筑暗面）、赭石（老墙暖面）、青灰（辅建筑）、米白（纸感高光）、朱（重点标记）、宣纸（背景）。**超出即违规**，自动扫描。
- **质感**：插画 / 明信片感，扁平 + 描边，不做写实渲染、不做花哨特效。
- **标签**：衬线体，不用无衬线抢戏。
- **视图角标**：固定显示数据来源。

### 6.2 准确性护栏（防编造 / 防神剧化）

1. 不凭空造建筑——视图里没有依据的形体不出现。
2. 高度、细节缺失处一律标"示意"，**不在界面上伪装成实测**。
3. 历史注记只来自开放数据并标注来源。
4. **"准确"的定义是四点**：地理落位正确、轮廓有据、历史标注有据、风格化诚实。**不是照片级实景。**

### 6.3 文案调性（三档 + 全局红线）

| 档 | 语气 |
|---|---|
| 文艺 | 克制、留白、画面感；策展导览体 |
| 硬核 | 史料密度高、出处前置、克制修辞 |
| 轻社交 | 轻量、具体、去说教；结尾有仪式感 |

**全局红线（任一违反即阻断）**
- ❌ 效率话术："一键生成""省时省力""再也不用查攻略"
- ❌ 口号式表述与表态引导
- ❌ 脸谱化、"神剧化"、廉价煽情
- ❌ 编队隐喻与集体动员语（"集合""带队""打卡任务"）
- ✅ 全程**个体第二人称**；用"具体细节 + 人的处境"替代评价性表述

> 示例：✓「这里不喧哗，却把 1920 年代的风都留住了。」 ✗「上海是伟大的革命城市！」 ✗「根据数据库返回，该地点类型为里弄。」

### 6.4 去"被组织"感的三个机制

| 机制 | 做法 |
|---|---|
| **入口反转** | 不给"报名"，给"出题"——你有多久、和谁、想要什么调性、从哪出发 |
| **角色代入** | 以"人物 × 年龄对照"为叙事锚（"他牺牲那年 24 岁，和你同岁"）；每点位一个可代入的人，而非一个机构 |
| **节奏主权** | ≤2h / 5–8 点 / 每点 3–8 分钟；**可断可续**，随时结束不判定"未完成" |

### 7.2 关键论断与口径纪律

- **纯软件 × 高深度 = 零观测，价格未知。** 现有 4 个纯软件样本全部是政府行政定价，不构成市场天花板证据。**未知 ≠ 零，也 ≠ 可行 = 必须先验证。**
- **对外材料禁写**："纯软件天花板 30 元""C 端无价可收""C 端锚定 150–199 元"——三条均已被撤回，评审会被追问。
- **归因未解**：付费买的是"履约"还是"深度"，在现有样本中完全共线，无法分离。若真相是"为深度付费"，我方 C 端定价空间远大于当前估计。
- **分母纪律**：覆盖率用「三馆年到访 410 万人次」，**不用平台注册数**（口径不同，一戳就破）；上历博量级只说"千人量级"，不引精确值。

### 7.3 ⚠️ 单位经济中最容易被漏掉的一项

> **真成本不是推理费用，是人工审核工时。**
> 红色题材内容必须人工兜底（G6）。推理成本在竞赛量级可忽略；**人工审核成本 >> 推理成本**。在 C 端 0–30 元档下，这是毛利的真正杀手。
> **要求**：轻履约定价实验的单位经济模型中，**必须把人工审核工时计入变动成本**，否则会系统性高估毛利率。

> **数析附录关键结论（轻履约单位经济）**：架构选择决定审核是变动成本还是固定成本——「离线灌库 + 点位池预生成 + 点位卡片库一次性审核（方案乙）」把审核从变动转为固定：30 元档（到馆自提）毛利率约 68%、68 元档约 65%；而逐次审核（方案甲）下 30 元档必然亏损、68 元档仅 32%。**轻履约可行性实质上取决于架构选择而非定价本身**，实验须绑定方案乙。馆方文创渠道分销在合理区间内优于自建 C 端直邮（免邮费 + 自然客流获客），谈判争取分成降至 25% 以下。

### 8.2 架构护栏 NG-10：坐标源可替换性

> **产品语言**：地图 v1 先出**示意图版**，后续在拿到真实坐标后，必须能**无缝替换**为真坐标版——**换的是数据，不是设计，更不是重做**。

**约束**
1. 示意图版与真坐标版**共用同一套点位信息结构**，字段构成完全一致；差异只体现在两个标记位的取值：**坐标来源**（人工核录 / 数据源 / 无）与**精度等级**（精确 / 近似 / 示意）。
2. 渲染与交互**只读坐标与呈现模式**，**不得依据"坐标来源"分出两套逻辑**。出现按坐标来源分支的实现即判违规。
3. 点位主键跨来源稳定；S1 的动作被定义为「回填坐标 + 翻转标记位」，**不得新增或重命名字段**。

**验收（Given / When / Then）**
Given 一条已渲染的示意图版路线
When 仅回填真实坐标并翻转坐标来源标记，不修改任何呈现逻辑
Then 地图正常渲染为真坐标版，配色 / 序号 / 距离标注均不回归

> **为什么必须写进 PRD 而不是留作实现细节**：这一条决定 S1 的"拉真坐标版"是**替换**还是**重做**。没有它，S1 的估算会翻倍，v1 省下的工期会在 S1 全数吐回去。

#### 9.3.1 U4 实证结论（2026-08-09 实测，提后更新）

> **性质**：本小节为截稿（2026-08-06）**之后**的实测更新，不改动原竞赛提交物 §9.3 / §11 D1 的拍板记录，仅补充实证结论与口径细化。实测日期 2026-08-09，方法为**直连上海图书馆开放数据实时接口**（`building/detail` + `building/event/list` + `persons/list`，API Key 已配），对白名单点位中两栋代表性建筑取证。

**① 核心主张成立，且可达层数高于原悲观预期（"两重"）**

- **武康大楼**：1924 邬达克设计；居住者更迭呈现 **4 个社会层**——侨民 → 电影圈（王人美） → 明星（赵丹 / 秦怡 / 孙道临） → 今民居。
- **丁香花园**：1862 李鸿章建 → 1940 遗老李经迈变卖 → 1942 张善绅办电影公司 → 1949 中共华东局（陈毅 / 潘汉年 / 刘亚楼 / 陈赓居此） → 1971 市委写作组，呈现 **5 个政权层**。
- 两栋楼均落在武康路—华山路—淮海路步行走廊上，地理连贯，且每层均可点开 `data.library.sh.cn` 实体 uri 溯源（实测样例 34/34 事实 100% 可溯源）。
- **结论**：「一栋楼装下不止一种人生」由可溯源馆藏坐实；**建筑 + 人物 + 事件 三重身份可达到且可验证**，高于原 §9.3 悲观底线"大概率仅建筑+事件两重"，**达到 R-03「目标 三重」**。

**② 字面"四重"（建筑 / 事件 / 诗词 / 纪年）不成立——诗词与纪年维度无法落到具体建筑**

- 上图**诗词**与**纪年**接口返回的记录**没有按武康路某栋具体建筑 geo-tag 的条目**；强行把某首诗、某条纪年安到某栋楼，等于无据断言，直接违反 §5.1 取证铁律（宁缺毋编）。
- 因此**不能用"诗词层""纪年层"凑满"四重"**；硬撑"四重人生"仍有评审现场被证伪的风险（与原 §9.3 预警一致）。

**③ 口径决策（细化 D1，非推翻）**

- 将对外核心 IP 由"四重人生"**重定义为「空间更迭层」**：保留 **建筑 + 人物 + 事件** 三个**可溯源**维度（实测可达 3–5 层），**放弃诗词 / 纪年** 两个无 geo-tag 维度。
- 全套对外表述同步改为"一栋楼的多重人生（空间更迭层）"，与 §1.5 抗反驳句"条目之间的关系"自洽，且不再依赖无法证实的维度。

**④ 对战略门槛与验收的影响**

- **S0-4 第二门槛（层数 ≥3）**：现可用 **建筑 + 人物 + 事件** 三个可溯源维度达成，**差异化在 ≥3 层口径下可辩护**；但"层数"须明确定义为"可溯源维度数"，**不计入无 geo-tag 的诗词 / 纪年**，否则门槛失真。长尾非空率 ≥60% 仍按原口径。
- **R-03 验收**：保底「建筑 + 事件 两重」不变；目标「三重」现实证可达（建筑 + 人物 + 事件），可保留。
- **US-4 / 核心 IP 演示口径**：从"四重人生"切到"空间更迭层"，避免评审现场一戳即破。

**⑤ 留存证据**：实测样例与验证结论见 `RedTrip_原型/样例_武康路一栋楼的四重人生.md` 与 `RedTrip_原型_验证结论.md`（同源 `RedTrip_原型/` 目录）；工程侧已将「四个一等公民中间产物 + 细粒度溯源」落为稳定契约（见 `RedTrip_G2G4_改造说明.md`），其中 `EvidenceGraph` 的 `dimension` 聚类即承载"空间更迭层"维度。

**② G1 命题分解（`packages/curator/redtrip_curator/proposition.py`）**

- LLM 把「用户原始留言 + 已取证摘要」拆成 **2–4 个研究命题**：`title` / `open_question` / `research_axes[]`（每项 `axis` + `hypothesis` + `dimension`）。`dimension` 限定为可用证据维度之一（person/event/building/era/poem/theme），并**映射到 `EvidenceGraph` 的 cluster id（`cl-{dimension}`）**，与 G2-2 证据图天然对齐。
- LLM 不可用 / 调用失败时回退规则式 `_research_axes`（按可用维度产出）。
- 实测（curated-live 真实上图数据）：`title=武康路轻社交史`、`open_question=20世纪上海的私密空间如何孕育跨文化轻社交？`、4 个 axis 正确映射到 `cl-event` / `cl-person`。

**③ 句子级溯源（`packages/curator/redtrip_curator/sentence_provenance.py`）**

- 在 **polish 之后**对 *最终* 叙事（story_card.body + 路线卡 body）逐句标注 `factual` / `connective`，并把每个事实句对齐到**事实目录**中的 `fact_uri`。事实目录只取自 `RoutePlan` 已取证 `IdentityLayer` 的 `source.record_id`，**LLM 只能在目录内选择，严禁编造**——与「事实只能源于取证证据」铁律一致。
- LLM 不可用 / 调用失败时回退启发式（句子命中该站点事实的人名 / 年份 token 即判 factual 并归入对应 `fact_uri`）。
- 实测：128 句 → 57 事实句、56 对齐，**coverage 0.9825**；未对齐事实句仅触发 **`G4-sentence[warn]`（warn 级，不阻断发布）**，Gate 仍 `passed=True`。

**④ 契约与校验**

- TS contracts（`packages/contracts/src/index.ts`）新增 `SentenceClaim` / `StopSentenceProvenance` / `SentenceProvenanceReport` 并挂到 `RouteEnvelope` 与 `CurationArtifacts`（可选字段，向后兼容）。
- `engine.py` 新增 G4-sentence warn 级校验；`pnpm -r typecheck` 通过（contracts + web 两包 Done）。

**⑤ 结论**

- 「每一句话都能追回馆藏」（PRD G1）从 *layer 级* 承诺升级为 *句子级* 可验证：渲染后叙事的每句事实句均带 `fact_uri`，未溯源事实句告警可见。
