# 产品概念与需求定义（PRD 级）

> 产品代号：**《城市记忆策展人》**（Curator of Shanghai Memory）
> 定位类型：文化策展型 Agent（上海图书馆开放数据竞赛参赛作品）
> 版本：v1 概念定义 · 可直接交付路线图规划师排期
> 上游输入：竞品分析（竞析）/ 用户洞察（瑞思）/ 市场数据（数析）

---

## 0. 结论前置

赛道不缺红色内容，缺**策展力**；年轻人不抵触红色，抵触**被组织**；市场已被验证但供给停在**点位串联**。
三者交汇处只有一个空位：**「权威 × 审美 × 个性化」同时成立**。这正是"上图真实馆藏 + 海派 2.5D + 生成式编排"能独占的位置。

因此 v1 只做一件事：**把上图跨库数据，实时策成一场只属于这个人的 90 分钟城市展览。**
不做线下、不做交易、不做社区、不做重沉浸。

---

## 1. 差异化定位与价值主张

### 主定位
> **别人给你一条红色线路；我们用上海图书馆的真实馆藏，为你策一场只属于你的城市展览。**

支撑护城河（竞析结论 3）：竞品有"点"，我们有**关系图谱**——`slc_red_event × slc_building × slc_era × souyun_poem` 的跨库关联，使"一栋楼四重人生"成为可复制的叙事母版，且长尾覆盖零边际成本。

### 三受众话术变体

| 受众 | 一句话 | 说服支点 |
|---|---|---|
| **年轻人（C 端）** | "不是打卡路线，是你的私人城市展览。90 分钟 6 个点，每个点都有一句别人不知道的原话。" | 独家信息 + 出片 + 不被组织（瑞思六把尺 1/2/3） |
| **竞赛评委 / 技术侧** | "跨库关联驱动的文化策展 Agent：事实必取 MCP 原文并标注 source，数据可溯 100%、编造 0、美学违规 0。" | 取证铁律 + 三阶段质检门禁 + 开放数据深度使用 |
| **官方 / B 端合作方** | "把 612 处红色资源，从'资源目录'变成可叙事、可批量生成的课程与线路供给。" | 补位而非抢流量；解决"游而不学"与"供给靠人肉不可规模化" |

**站位声明**：我们不与"红途"比资源量（9827 项、727 万用户），我们做它上面缺的那一层——**叙事组织层**。

## 2. 年轻化策略

### 2.1 从"被组织"→"主动入戏"（三个机制）

| 机制 | 具体做法 | 对抗的旧模式 |
|---|---|---|
| **入口反转** | 不给"报名"，给"出题"：你有多久 / 和谁 / 想要什么调性 / 从哪出发 → Agent 现场策展 | 集合—排队—听讲 |
| **角色代入** | 以"人物 × 年龄对照"为叙事锚（"他牺牲那年 24 岁，和你同岁"）；每点位一个可代入的人，而非一个机构 | 脸谱化讲解 |
| **节奏自主** | ≤2h / 5–8 点 / 每点 3–8 分钟；**可断可续**，随时结束不判定"未完成" | 全程跟队、写心得 |

### 2.2 社交货币四件套（瑞思结论 4）
1. **可保存路线图**（2.5D 长图，自带统一视觉）
2. **人物故事卡**（含年龄对照句 + 馆藏出处角标）
3. **今昔同框图**（历史影像/记载 × 当下机位）
4. **机位卡**（明确指认"站哪拍、拍什么、什么时段光好"）

四件套均为**可直接发布的成品素材**，不需用户二次加工——这是 persona A 的付费/传播理由。

### 2.3 三 persona 打法

| Persona | 最短说服路径 | v1 必须给到 |
|---|---|---|
| **A 梧桐区文艺策展人**（22–28 女，传播源头） | 审美调性统一 + 出片点被指认 | 素材包一键导出、机位卡、6 色统一视觉 |
| **B 硬核考据党**（20–30，可信度背书者） | 每条事实可展开原文与出处 | 溯源抽屉、跨库"四重人生"时间轴、"暂无收录"诚实标注 |
| **C 情侣闺蜜轻社交**（21–30，2 人） | 90 分钟轻量 + 结尾仪式感 + **红色不尴尬** | 双人 90 分钟档、去说教化文案调性、收尾同框仪式 |

> **C 是最难一关**：文案层面全局禁用口号式表述与表态引导，改用"具体细节 + 人的处境"。这一条写入美学/风格护栏，由质检门禁强制。

## 3. 高品质标准（品质规格表）

把瑞思"六把尺"与既有质检 KPI 合并为**可验收规格**。任何一项 FAIL → 门禁拦截，不出图。

| # | 维度（尺） | 可验收标准 | 验收方式 |
|---|---|---|---|
| Q1 | **信息独家** | 每条路线 ≥3 条来自 MCP 原文的"非百度可得"细节；每点位 ≥1 条 | 抽检反查 + 细节密度计数 |
| Q2 | **出片点指认** | ≥50% 点位含机位卡（站位/朝向/建议时段），文字具体到可执行 | 人工策展复核 |
| Q3 | **节奏可断可续** | 总时长 ≤120min；点位 5–8 个；单点讲述 3–8min；任意点位可终止且有收尾 | 自动：时长/点数校验 |
| Q4 | **清晰路线图** | 2.5D 地图含序号、连线、步行距离与预计耗时；地理落位正确 | 自动：坐标/序号完整度 |
| Q5 | **审美调性统一** | 海派 6 色 palette 锁死，越界即违规；flat + toon outline；标签用衬线体 | 自动：palette 扫描 |
| Q6 | **避坑信息齐全** | 开放时间 / 是否可入内 / 是否需预约；**无数据时明示"未收录"，禁止推测** | 自动：字段非空或显式声明 |
| Q7 | **数据可溯**（既有 KPI） | 100%：所有事实字段 `source` 非空且可达 | 自动：schema + 链接扫描 |
| Q8 | **编造率**（既有 KPI） | 0：红队用例集全通过 | 红队回归 `tests/redteam_check.py` |
| Q9 | **美学违规**（既有 KPI） | 0 | 自动 palette / "不造建筑" / 示意标注检查 |
| Q10 | **叙事分寸** | 不脸谱化、不口号化、不"神剧化"；C persona 尴尬度人工评分 ≤2/5 | 人工策展复核 |

## 4. 核心体验与功能设计

### 4.1 主流程（五步）
```
① 出题（≤30s）→ ② Agent 策展（取证·缝合·排点）→ ③ 2.5D 城市记忆地图
→ ④ 漫步（点位卡片·可断可续）→ ⑤ 收尾素材包（一键导出）
```

### 4.2 个性化输入：既有 5 槽位 → **6 槽位**
既有：人群 · 场景 · 时长 · 风格 · 交付形
**新增：同行结构**（独自 / 2 人 / 3–4 人小团体）——瑞思发现 2–4 人小团体是最大供给空档，必须成为一等输入。
缺 ≥3 槽位才问 1 问，否则按默认 persona 假设并显式声明（沿用既有 SOP）。

### 4.3 职责分工：Agent（上图 MCP 策展）vs 前端（2.5D 渲染）

| 能力 | 归属 | 说明 |
|---|---|---|
| 取证检索与 `source` 标注 | **Agent** | `slc_red_event` / `slc_building` / `slc_era` / `souyun_poem` 原文抓取 |
| 跨库缝合"一栋楼四重人生" | **Agent** | 以建筑为主键，按纪年串事件/诗词，产出时间轴数据 |
| 选点与排序 | **Agent** | 步行可达 + 时长约束 + 兴趣权重 + 同行结构 |
| 叙事生成（故事卡/年龄对照/独家原句） | **Agent** | 只引用不编造；风格随"调性"切换 |
| 机位卡文案 | **Agent** | 基于建筑朝向与场景描述生成，标注"示意" |
| 避坑信息层 | **Agent** | 有则取、无则明示"未收录" |
| JSON 信封契约输出 | **Agent** | `intent/theme/logic_line/aesthetic/scenario/why_visit/sources/blocks` + 新增 `route/companions` |
| 2.5D 城市记忆地图渲染 | **前端** | OSM footprint 挤出 + 海派 6 色 + 缎带式 ribbon 路线 |
| 卡片系统（故事卡/今昔同框/机位卡） | **前端** | 统一模板，Agent 只供内容不管样式 |
| 素材包导出（长图 + 卡片组） | **前端** | 一键成图，无需二次编辑 |
| 断点续走 / 溯源抽屉 / 时间轴切换 | **前端** | 本地状态，不回调 Agent |

> **解耦原则**（沿用 2.5D 设计文档）：准确性来自真实数据（Agent），好看来自一致风格化（前端），两层不互相将就。

## 5. 三个正交产品目标

| 目标 | 含义 | 核心指标 |
|---|---|---|
| **G1 可信（真）** | 每一句话都能追回上图馆藏 | 数据可溯率 = 100%；编造率 = 0 |
| **G2 可传（美）** | 产出即社交货币，无需二次加工 | 素材包导出率 ≥40%；美学违规 = 0 |
| **G3 可变（个性化 × 规模）** | 任意合法出题都能在时延内策出合规路线 | 策展成功率 ≥95%；P95 时延 ≤60s；覆盖点位数 |

正交性：G1 管"真"、G2 管"美与传播"、G3 管"规模与个性化"，任一提升不必然带动另两个，可独立度量与归因。

## 6. 用户故事（Given / When / Then）

**US-1（Persona A · 素材包）**
Given 我是内容创作者，周六下午空 2 小时，想要"梧桐区+老洋房"调性
When 我填完出题并生成路线
Then 我得到 6 点位 2.5D 路线长图 + ≥3 张机位卡，可直接导出发布，视觉风格与我的账号调性一致

**US-2（Persona B · 溯源）**
Given 我是考据党，看到卡片写"这栋楼 1927 年曾是某机关联络点"
When 我点开该句旁的来源角标
Then 展开 MCP 原文片段与库名字段；若该细节无收录，明确显示"暂无数据支撑"，而不是给我一段听起来合理的话

**US-3（Persona C · 双人轻社交）**
Given 我和对象当天起意，只想走 90 分钟且不想被说教
When 我选择"2 人 / 轻松 / 90 分钟"
Then 得到 5 点位路线，文案无口号式表述，结尾给出一个同框机位与纪念卡，全程可随时结束

**US-4（跨库叙事 · 护城河演示）**
Given 我对某栋建筑感兴趣
When 我切换到该点位的"时间轴"
Then 看到同一坐标上由事件/纪年/诗词缝合出的多重身份，每层标注来源

**US-5（质检门禁 · 内部）**
Given Agent 生成了一版路线
When 进入交付前门禁
Then 自动跑 schema / 来源可达 / palette / 槽位四项校验 + 红队回归；任一 FAIL 则拦截并回写失败原因，不向用户输出

| R-12 | 溯源抽屉（逐句展开 MCP 原文） | P1 | 任一事实句可展开原文与库名 | 2 人日 |

| R-15 | 纪念票根 / 结尾仪式感 | P2 | C persona 收尾卡片 | 1 人日 |

## 8. Non-goals（明确不做）

1. **不做线下履约**——不组团、不带队、不排班、不卖门票、不做导游调度。
2. **不做交易闭环**——v1 不接支付；88–128 元客单价仅作商业模型论证，不在 v1 落地。
3. **不抢官方流量、不堆资源目录**——不与"红途"比资源量，只做其上缺的叙事组织层。
4. **不做剧本杀级重沉浸**——不做 AR / 实景演绎 / 道具 / NPC。
5. **不做 UGC 社区**——不做发帖、评论、关注体系。
6. **不做全国覆盖**——v1 仅上海，优先梧桐区 + 一大周边。
7. **不替代地图 App**——不做实时导航与逐向路径规划，只给可视化路线与步行距离。
8. **不做照片级实景三维**——沿用既有判断，风格化 + 诚实标注"示意"。
9. **不生成无出处的历史事实**——宁缺毋编，"暂无数据支撑"是合法输出。

## 9. 待确认问题

### 9.1 数据待核实（来自数析）
- Q1 红色旅游细分市场无权威规模口径 → 对外表述需标注"估算/媒体口径"
- Q2 上海 1.6 亿人次/年为粗估，需回溯原始出处
- Q3 策展级客单价 300–500 元为估算，无公开成交样本
- Q4 部分媒体引用数据（如小红书搜索 +30 倍）需核实原始统计口径与时间窗

### 9.2 假设待验证（来自瑞思）
- Q5 2–4 人小团体 × 0–39 元档确为供给空档？（建议：小样本供给盘点）
- Q6 "红色不尴尬"社交顾虑的真实强度（建议：C persona 文案 A/B 定性测试）
- Q7 "年龄对照"共情效率是否显著高于普通叙事（建议：故事卡两版对照）

### 9.3 需用户/主理人拍板
- Q8 **模型供应商与调用配额**（影响 G3 时延目标 P95 ≤60s 是否可达）
- Q9 **天地图 Key 与商用授权**（选型表已标 ⚠️ 待确认；若不可用，需确定 OSM-only 降级方案）
- Q10 **MCP 字段覆盖度实测**：`slc_building` 是否含开放时间/可入内等避坑字段？直接决定 R-11 是 P1 还是砍掉
- Q11 **v1 地理范围**是否收敛到梧桐区 + 一大周边（建议：是，保 P0 可交付）
- Q12 **竞赛提交形态**：Web 端 / 小程序 / 视频演示，决定 R-05、R-08 的实现深度
- Q13 **是否在 v1 保留 B 端演示切片**（R-16 为 P2，若评委关注商业闭环可上提）
