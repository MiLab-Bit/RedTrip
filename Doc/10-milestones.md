## 3. 建议开发顺序（脚手架之后）

```
1. packages/contracts + content/whitelist 模板
2. apps/api health + 假数据 curate（契约打通）
3. apps/web 出题 → 渲染假 envelope（UI 闭环）
4. library-client + 本地索引 + S0 脚本
5. curator Evidence → Plan（先无 LLM）
6. NarrativeGen + Gate
7. Map 示意图
8. 红队接入
9. 时延：预生成 / 缓存
```

原则：**先假数据打通契约，再换真数据；先骨架，再叙事。**
